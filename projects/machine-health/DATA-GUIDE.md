# 팬 데이터와 제조 설비: 처음 배우는 도메인 지식

이 문서는 입문 설명과 Codex의 데이터 확인 결과다. 사용자가 이해하거나 실습을 완료한 기록은 아니다.

## 공장에서 무엇이 이상해지는가

제조업은 재료를 가공·조립하여 제품을 만드는 일이다. 제품을 만드는 설비와 제품 자체는 서로 다른 관찰 대상이다.

| 대상 | 질문 | 흔히 쓰는 데이터 |
|---|---|---|
| 제품 품질 | 만들어진 부품에 흠집·변형·누락이 있는가? | 제품 사진, 검사 측정값 |
| 설비 상태 | 제품을 만드는 기계가 정상적으로 작동하는가? | 소리, 진동, 전류, 온도 |
| 공정 상태 | 생산 과정이 정상 범위를 벗어나는가? | 압력, 유량, 온도, 제어 기록 |

이번 팬 소리 프로젝트는 설비 상태를 관찰한다. 산업용 팬은 공기나 가스를 이동시키는 설비다. 모터가 회전축을 돌리고, 축에 붙은 날개가 공기를 움직이며, 베어링은 축이 회전하도록 지지한다. 마찰·회전·공기 흐름이 소리/진동을 만든다. 날개 손상, 불균형, 막힘 등이 생기면 소리가 바뀔 수 있다. 일반 설명이며 선택 음원 각각의 고장 원인을 확인한 것은 아니다. 관련 MIMII DG 논문은 팬 이상 유형에 날개 손상·불균형·막힘·과전압을 기술한다.

| 용어 | 쉬운 의미 | 모델에서 중요한 이유 |
|---|---|---|
| 운전 조건 | 속도·부하·운전 모드 등 기계가 일하는 조건 | 정상이어도 조건에 따라 소리가 달라짐 |
| RPM | 1분 동안 회전하는 횟수 | 회전에 따른 주기 성분을 이해하는 기준 |
| 부하 | 설비에 요구되는 일의 정도 | 같은 기계라도 부하가 달라지면 신호가 바뀔 수 있음 |
| 정상 | 정해진 조건에서 기대되는 상태 | 하나의 고정 파형이 아니라 가능한 변화 범위를 배움 |
| 이상 | 기대 상태에서 벗어난 관측 | 고장 원인까지 확정하는 용어는 아님 |
| 열화 | 시간이 지나며 상태가 나빠지는 과정 | 조기경보·수명예측에는 연속 열화 자료가 필요 |
| 경보 | 점수를 바탕으로 확인을 요청하는 판단 | 오탐은 점검 부담, 미탐은 놓친 이상 |

예를 들어 1,800RPM은 1초에 30회 회전한다. 회전 주기를 이해하기 위한 예시이며 실제 음원의 RPM을 확인한 수치가 아니다. 최대 음향 피크가 반드시 30Hz라는 뜻도 아니다.

정상 팬의 속도 변화, 옆 설비의 소음 변화, 팬 자체의 손상은 모두 소리를 바꿀 수 있다. 모델은 관측이 달라졌다는 것과 설비 이상을 구별해야 한다. 이것이 domain shift를 다루는 이유다.

## 준비한 데이터

현재 실습은 **DCASE 2025 Task 2 개발 데이터의 fan**이다. 받은 WAV 12개 모두 단일 채널, 16,000Hz, 10초다. 한 파일에는 160,000개의 시간 순서 표본이 있지만 독립적인 160,000건의 학습 사례가 아니다.

기계 소리와 환경 소음을 이용한 실험 벤치마크다. 실제 공장을 고장 순간까지 장기간 관찰한 로그로 간주하지 않는다. 개발 데이터의 정상/이상 라벨은 파일명으로 확인할 수 있다. 모델에 파일명이나 normal/anomaly 문자열을 입력하면 정답 누수가 된다.

| 분할 | 정상 | 이상 | 쓰임 |
|---|---:|---:|---|
| source train | 990 | 0 | 충분한 정상 데이터로 기준 학습 |
| target train | 10 | 0 | 다른 조건의 정상 데이터가 적게 주어진 상황 |
| source test | 50 | 50 | 기존 조건에서 평가 |
| target test | 50 | 50 | 다른 조건에서 평가 |

별도의 supplemental 소음 자료도 있으며 현재 12개에는 포함하지 않았다. 임곗값과 특징 선택은 테스트에서 조절하지 않고 train 안의 별도 검증 분할 등으로 고정한다. source/target은 정상/이상의 다른 이름이 아니다. 각각의 환경에 정상과 이상이 모두 있다. test의 이상 비율 50%는 평가 설계이며 실제 공장의 이상 발생률이 아니다.

## 실제 원본 속성 표에서 확인한 조건

`data/attributes_00.csv`를 원본 ZIP에서 받아 확인했다. 컬럼은 file_name, d1p, d1v이며 팬의 조건 키는 n이다.

| 분할·환경 | 조건 코드 | 원본 표의 건수 |
|---|---|---:|
| train source | A, B, C | 각각 330 |
| train target | D, E | 각각 5 |
| test source | A, B, C | 각각 34, 34, 32 |
| test target | D, E | 각각 50 |

익숙한 조건과 덜 익숙한 조건을 나누어 평가할 수 있다. A~E는 속성 표의 범주 코드다. letter만으로 특정 실제 공장, RPM, 고장 종류를 단정하지 않는다. 최신 데이터 코드와 과거 MIMII DG의 section 번호를 같은 것으로 간주하지 않는다.

예시 `section_00_source_test_anomaly_0000_n_B.wav`는 section 00, source 환경, test 분할, 이상 라벨, 개별 번호 0000, 조건 n=B를 나타낸다. 라벨을 보고 비교하는 EDA와 라벨 없이 신호에서 점수를 만드는 모델 입력을 분리한다.

## 소리를 어떻게 읽는가

| 표현 | 읽는 법 | 한계 |
|---|---|---|
| 파형 | 가로 시간, 세로 소리 표본의 크기 | 여러 소리 성분이 섞임 |
| RMS | 신호 크기를 요약하는 숫자 | 큰 소리가 곧 고장은 아님 |
| 주파수 스펙트럼 | 어떤 주기 성분이 강한지 | 피크 하나로 고장 부품을 확정하지 않음 |
| 스펙트로그램 | 가로 시간, 세로 주파수, 색은 해당 성분의 세기 | 조건·소음도 그림을 바꿈; 색상 축을 맞춰야 함 |

`reports/sample-spectrograms.png`는 source/target의 정상/이상 예시 네 개를 동일 색상 축으로 표시한다. 색은 고장 부위나 모델 attention이 아니다. 현재 코드는 모델을 학습하지 않았으며 특징과 신호를 관찰하는 단계다.

## 2026판과의 차이

2026 Task 2는 가까운 위치와 먼 위치의 두 채널 녹음을 이용한 noise-aware 탐지를 다룬다. 두 채널은 정상/이상 한 쌍이 아니라 같은 관측의 다른 위치 음향이다. 개발 데이터의 일부 종류는 실제 두 마이크 녹음이고 일부는 impulse response로 만든 모사 두 채널이다. 현재 단일 채널 2025 실습과 파일 형식·해석을 섞지 않고, 이후 소음 강건성 연구 단계에서 별도로 확장한다.

## 첫 수업

1. source 정상/이상 음원 하나씩 들어보기.
2. 파형·스펙트로그램에서 보이는 차이를 묘사하기. 고장 원인을 찍는 것은 아직 목표가 아니다.
3. target의 정상 소리에도 경보가 날 수 있는 이유를 생각해보기.
4. 임곗값 초과의 ‘점검 필요’와 ‘베어링 고장 확정’을 구분하기.

지금은 팬 구조, 정상/이상/운전 조건, WAV/파형/스펙트로그램, 오탐/미탐을 이해하면 충분하다. 주파수별 고장 진단과 수명예측은 해당 데이터를 다룰 때 배운다.
