# DEUX 참고 사이트 재분석과 시각 설계 방향

분석일: 2026-10-09 (한국 시간)

참고: https://deux-midterm.vercel.app/

## 관찰 범위

공개 HTML의 최종 CSS, 장면 정의와 카메라 전환 코드를 읽었다. 실제 Chromium WebGL 렌더링으로 생성한 중력보상·임피던스 장면의 스크린샷도 확인했다. 첫 화면 캡처는 등장 애니메이션 도중이므로 최종 표지의 타이포그래피 평가에는 사용하지 않았다. 웹 검색 도구와 CUA 브라우저는 접근 오류가 있었지만, 독립 Chromium 렌더링과 공개 소스 검토는 성공했다.

## 기존 구현에서 놓친 핵심

현재 포트폴리오는 발표 화면의 외형만 갖춘 문서다. 내용이 바뀔 때 시각 대상은 사라지거나 작은 정적 그림으로 대체된다. 참고 사이트는 동일한 로봇을 계속 다른 거리와 각도에서 보여주며, 장면 자체가 설명의 일부다. 16:9 비율과 짧은 문장만 적용해도 이 차이는 해결되지 않는다.

앞선 리뷰는 반복 문구와 불필요한 조작을 찾는 데는 유효했다. 그러나 4장으로 압축하고 시각화를 제거하는 처방만 적용해, 사용자가 요청한 공간감·연속성·과감한 장면 구성이 더 약해졌다. 장 수를 목표로 삼지 말고 핵심 주장마다 적절한 촬영 구도와 근거를 배치해야 한다.

## 참고 사이트의 실제 시각 문법

- **하나의 무대와 하나의 대상:** 검정 화면에 같은 로봇이 계속 남는다. 다음 장은 새로운 그림을 여는 동작보다 대상의 다른 부분을 보는 동작에 가깝다.
- **전체 → 부분 → 전체:** 소개에서는 로봇 전체를, 기능 설명에서는 팔을 확대한다. 장면에 따라 몸통이나 반대쪽 팔이 사라져 초점이 명확해진다.
- **과감한 크기:** 로봇의 일부가 화면 밖으로 잘릴 정도로 가까이 온다. 정사각형 카드 안에 안전하게 넣은 썸네일과 다른 인상을 만든다.
- **한국어 설명과 대상의 결합:** 왼쪽은 짧은 주장·근거·조작, 오른쪽은 해당 주장의 대상이다. 본문 뒤의 어두운 그라데이션이 가독성을 확보하면서 무대는 하나로 보인다.
- **좌표를 가진 설명:** 관절 라벨은 대상 위에 붙는다. 오른쪽에 따로 쓴 목록보다 무엇을 설명하는지 즉시 알 수 있다.
- **원인과 결과가 있는 조작:** 중력보상과 임피던스 버튼은 대상의 상태와 수치를 바꾼다. 이 조작은 설명을 검증하는 역할을 한다.
- **장면의 리듬:** 내용 화면 사이의 챕터 구분, 큰 외곽선 글자, 세로 진행 레일이 발표 전체의 흐름을 만든다. 장면마다 같은 제목·카드 그리드를 반복하지 않는다.

소스에서는 1600×900 좌표계를 창에 비례해 축소하며, 장면별 카메라 위치·초점·보이는 팔·확대 정도를 따로 정의한다. 전환은 이 상태들을 보간한다. 따라서 핵심 구현 단위는 카드 템플릿보다 `장면 상태`다.

## AML에 적용할 구체 설계

금융의 중심 대상은 거래 네트워크로 정한다. 로봇을 흉내 낸 장식물이 아니라 계좌·거래·이웃 정보라는 연구 대상을 공간 안에서 보여준다.

| 장면 | 화면에서 설명할 것 | 같은 거래망의 변화 |
| --- | --- | --- |
| 연구 표지 | 연구의 질문과 제목 | 청록빛 거래망 전체. 큰 덩어리가 오른쪽 공간을 차지한다. |
| 데이터 | 계좌는 점, 거래는 방향 있는 연결 | 전체망의 한 거래로 접근한다. 송신·수신 계좌만 밝게 남는다. |
| 비교 설계 | 거래 특징 모델과 관계를 쓰는 모델 | 같은 거래를 유지하며 주변 이웃이 펼쳐지고 메시지 전달 방향이 드러난다. |
| 실험 결과 | 보고서에 근거한 주 지표와 비교 | 거래망은 어둡게 물러나고 정확한 그래프가 중심이 된다. 모델 성능을 노드 색으로 꾸며내지 않는다. |
| 추가 분석 | 오류·날짜별 변화·비교 조건 중 실제 근거가 있는 핵심 | 필요한 표나 사례를 크게 보여준다. 근거가 없으면 이 장면을 만들지 않는다. |
| 결론 | 이번 실험이 지지하는 주장과 한계 | 전체망으로 돌아오며 결론과 출처를 배치한다. |

장 수는 파일 내용을 확인해 결정한다. 6장이라는 숫자를 지키기 위해 내용을 만들거나 실제 근거를 버리지 않는다.

### 화면 규격

- 배경은 순검정에 가까운 단색. 청록은 선택된 금융 구조와 핵심 수치에 집중한다. 로봇 페이지는 동일한 체계에서 주황을 쓴다.
- 데스크톱은 16:9 발표 무대. 본문은 왼쪽 약 42%, 대상은 오른쪽 55~65%를 사용한다. 같은 사각 카드 두 개로 나누지 않는다.
- 중심 거래망의 화면 높이는 약 65~80%. 가장자리의 일부 노드는 잘려도 좋다. 주석은 화면 안에 남긴다.
- 한국어 주장 제목은 2줄 이하, 본문은 2~3개 근거로 제한한다. 수식·표는 결과 장에서 충분한 넓이를 준다.
- 장면 간 전환은 약 0.7~1초. 위치·배율·깊이·강조를 연결하고 글은 짧게 등장한다. 사용자가 다음 장으로 갈 때 애니메이션을 기다리게 하지 않는다.
- 같은 노드 ID를 유지한다. 전체망이 새 무작위 그래프로 바뀌면 연속성이 깨진다.
- 중앙 거래 1개와 설명용 주변 계좌를 약 20~36개 사용한다. 전경 노드는 선명하게, 후경은 작고 어둡게 표현해 깊이를 만든다. 실제 분석 결과로 오해하지 않도록 예시 표시를 한 곳에 둔다.
- 챕터 레일 또는 짧은 하단 이동 중 하나를 주 탐색으로 쓴다. 중복 목차·버튼·링크를 화면 주변에 모두 붙이지 않는다.
- 모바일은 동일 의미의 간결한 2D 그림과 세로 본문. 16:9 화면을 읽을 수 없을 정도로 축소하거나 가로 회전을 강제하지 않는다.
- 움직임 줄이기는 장면의 최종 상태를 즉시 보여준다. 지속 회전·입자 흐름·카메라 이동을 함께 멈춘다.

## 무엇을 유지하고 무엇을 피할지

깊이와 초점 변화, 크고 연속적인 중심 대상, 한국어 주장, 실제 결과 비교는 강화한다. 설명과 무관한 영어 구호, 매 장 같은 카드 배치, 무작위 장식 그래프, 선택하지 않으면 수치를 비교할 수 없는 UI는 만들지 않는다.

참고 사이트의 Three.js·GSAP 번들과 로봇 자산을 복사할 필요는 없다. 우리 데이터에 맞는 최소한의 장면 시스템을 쓰되, 기술을 줄이려는 이유로 시각적 핵심까지 삭제하지 않는다. 단순 2D SVG를 박스 안에 작게 놓는 이전 접근으로 돌아가지 않는 것이 중요하다.

## 검수 기준

1. 발표의 첫 화면에서 큰 중심 대상이 즉시 보이는가?
2. 다음 장으로 갈 때 동일 대상을 계속 보고 있다는 인식이 유지되는가?
3. 장면의 확대·강조가 본문의 설명 대상과 일치하는가?
4. 결과는 보고서의 수치·분할 조건·평가 지표와 일치하는가?
5. 작은 창·모바일에서는 읽을 수 있는 글자 크기와 2D 대체가 유지되는가?
6. 움직임 줄이기 및 그래픽 실패 시에도 모든 본문과 결과가 읽히는가?

분석용 스크린샷과 코드 관찰만으로 실물 로봇 동작의 정확성이나 참고 사이트 전체 성능까지 검증한 것은 아니다.
