# DEUX: 실제 조작과 공개 코드로 확인한 구성

분석일: 2026-10-09. 대상: https://deux-midterm.vercel.app/

## 확인 방법과 범위

Playwright에서 Chrome을 실행해 슬라이드 레일, 중력보상 버튼, 두 임피던스 모드, 텔레오퍼레이션 제한과 신호 끊기, 영상 모달, 키보드와 휠 이동, 드래그·확대·초기화를 조작했다. 공개 HTML의 구현과 화면을 함께 대조했다. 원본 프로젝트 저장소나 제작자의 작업 환경에 접근한 것은 아니다.

분석 자료는 로컬 `site-preview/reference/`에 보관했다. `interact.cjs`, `verify.cjs`는 재현용 스크립트이고, `source.html`은 당시 브라우저가 받은 공개 코드와 렌더링된 DOM이다. 스크린샷 및 임시 자료는 Git에서 제외한다. SwiftShader 소프트웨어 WebGL 환경이라 실제 GPU 성능이나 정확한 애니메이션 소요 시간은 평가하지 않는다.

재검증 기록 `verified-interactions.json`에서 다음 상태 변화를 확인했다. 처짐 상태는 끈 뒤 0 → 약 0.715, 다시 켠 뒤 약 0.111로 감소했다. 두 밀기 버튼은 같은 오차 0.55에서 출발했으며 이후 서로 다른 복귀 상태가 관측됐다. 신호 끊기 직후 `frozen=true`, 3.2초 후 `false`였다. 드래그로 yaw/pitch가 0/0 → -0.56/0.25, Shift+휠로 zoom이 1 → 0.92, 더블클릭 후 0/0/1로 복원됐다. 키보드와 일반 휠은 각각 다음 슬라이드 위치로 이동했다. 이 수치는 재현 환경의 내부 상태 관측이며 로봇의 물리 측정치가 아니다.

## 결론: 조작 가능한 18장짜리 발표 자료

페이지마다 별도 그림을 배치하는 구조가 아니다. 하나의 3D 무대를 유지하면서 본문, 카메라, 로봇의 자세와 표시 부품을 장면별로 바꾼다. 사용자는 같은 대상을 전체 → 부분 → 비교 → 전체 순서로 보고, 버튼으로 설명의 원인과 결과를 확인한다.

검정 배경이나 3D 자체보다 중요한 요소는 세 가지다.

1. **화면을 크게 차지하는 설명 대상:** 로봇이 카드 속 삽화가 아니라 화면의 주인공이다. 확대하면 일부가 화면 밖으로 잘린다.
2. **한 장에 하나의 주장:** 제목, 간단한 설명, 조작 버튼, 해당 부품이 같은 내용을 말한다.
3. **대상의 연속성:** 슬라이드를 넘겨도 앞서 보던 로봇이라는 인식이 유지된다. 기능에 따라 카메라와 자세가 바뀐다.

## 실제 구성 기술

| 영역 | 공개 코드에서 확인한 구현 | 화면에서의 역할 |
| --- | --- | --- |
| 본문 | HTML·CSS, 직접 DOM 조작 | 텍스트·표·버튼·진행 레일 |
| 발표 프레임 | 1600×900 좌표계를 창에 비례 축소 | PPT처럼 장마다 동일한 구도 유지 |
| 이동 | CSS `scroll-snap`, `scrollIntoView`, 키보드 이벤트 | 휠·레일·화살표로 한 장씩 이동 |
| 현재 장 판정 | `IntersectionObserver`와 스크롤 종료 보완 검사 | 장면과 진행 표시를 갱신 |
| 3D | Three.js, `WebGLRenderer`, 관절 계층과 메시 | 실제 입체 로봇과 관절 자세 |
| 장면 전환 | `SCENES`, `gotoScene`, GSAP | 카메라 위치·초점·부품 표시를 함께 변경 |
| 표면 표현 | 흰색 `MeshToonMaterial`, 3단계 명암 | 검정 배경에서 읽기 쉬운 로봇 형태 |
| 윤곽선 | 법선 방향으로 확장한 뒷면 메시 | 부품의 검은 외곽선 |
| 후처리 | 직접 작성한 렌더 타깃·블러·합성 셰이더 | bloom, 약한 grain, vignette, 흰 챕터 화면 합성 |
| 영상 | 외부 MP4를 여는 HTML video 모달 | 브라우저 데모와 실제 시연 근거를 구분 |

검토한 전달 코드에는 Three.js·GSAP 번들과 압축 메시 데이터가 인라인으로 들어 있다. 메시 팩을 gzip 해제하고 바이너리 위에 typed array를 만들어 지오메트리를 구성한다. 로봇이 단순 GIF나 동영상으로 돌아가는 방식은 아니다. 소스의 메시 설명은 MuJoCo에서 가져온 구조를 언급하지만 원본 자산 제작 과정까지 확인한 것은 아니다.

이 결과만으로 제작에 사용한 편집기, AI 도구, 디자인 도구 또는 전체 빌드 환경을 단정할 수 없다. React·Next.js가 이 효과의 필수 조건이라는 근거도 없다.

## 눌러 보면서 확인한 인터랙션

### 중력보상

`받쳐 주기 켜기`와 `끄기`가 선택 상태와 화면의 받침 상태를 바꾼다. 끈 뒤 팔 처짐 표시가 증가했고 켠 뒤 감소했다. 코드도 같은 상태값을 사용하여 팔의 유지 자세와 처진 자세 사이를 보간한다. 화면의 처짐과 토크 표시는 브라우저의 설명용 계산이며 실시간 로봇 센서 값이 아니다.

### 임피던스

`COMPLIANCE 로 밀기`와 `IMPEDANCE 로 밀기`는 같은 밀림 깊이에서 출발해 복귀 양상을 비교한다. 팔 자세, 모드 선택, 밀리는 중/복귀 중 표시가 함께 바뀐다.

중요한 구분: 최신 `simulate` 구현은 시각적인 차이를 강조하려고 별도의 `vkp`, `vkd`를 사용한다. 표시용 설정값과 애니메이션 계산 계수가 동일하지 않다. 따라서 이 데모의 복귀 시간을 실제 로봇 성능 수치로 인용하면 안 된다. 코드에 옛 슬라이더 처리와 주석은 남아 있지만 현재 DOM에는 input/select가 없었다.

### 텔레오퍼레이션

제한 켜기/끄기는 상태값과 선택 표시를 바꾼다. 구현은 제한이 없을 때 진동 성분을 더하고 추종 속도 상한을 바꾼다. 신호 끊기는 브라우저의 추종 목표 갱신을 멈췄다가 2.6초 후 해제하도록 작성되어 있다. 실제 로봇이나 네트워크 연결을 차단하는 버튼이 아니다.

### 대상 조작과 영상

드래그는 모델의 시점을 바꾸고, Shift+휠은 확대/축소, 더블클릭은 초기 구도로 복귀한다. 일반 휠은 슬라이드 이동에 남겨 둔다. 버튼·본문 등의 조작과 회전이 충돌하지 않도록 제외 영역이 있다.

시연영상 버튼은 MP4 모달을 열며 Escape로 닫힌다. 첫 확인에서 미디어가 준비되기 전 상태까지 관측했으므로 영상 전체 재생 성공이나 영상 내용 검증을 주장하지 않는다.

## 스크롤 효과의 정확한 구조

1. 브라우저의 스크롤 스냅이 다음 슬라이드에 정착시킨다.
2. 새 슬라이드가 활성화되면 해당 `data-scene`을 선택한다.
3. GSAP이 약 0.95초, `expo.out`으로 카메라와 시각 상태를 전환한다.
4. 제목과 본문은 별도의 등장 애니메이션으로 들어온다. 제목에는 임시 글리프가 원문으로 확정되는 효과가 있다.
5. 큰 외곽선 영어 단어와 진행 레일, 흰 챕터 구분 화면이 발표의 리듬을 만든다.

즉, 스크롤 위치의 모든 픽셀을 카메라에 연속 대응시키는 구성과는 다르다. GSAP 코어에 ScrollTrigger라는 문자열이 들어 있다고 해서 실제 페이지가 ScrollTrigger로 스크롤을 제어한다고 판단하면 안 된다.

상시 자동 회전, 카메라 표류, 일부 입자 효과는 현재 코드에서 꺼져 있거나 제거되었다. 효과 이름이나 과거 주석만 읽고 현재 기능으로 나열하면 부정확하다. 카드 틸트·포인터 하이라이트·자석 버튼은 보조 효과이며 중심 설계는 설명 대상의 장면 전환이다.

## 현재 AML에서 바꿔야 할 핵심

현재 `web/aml-scene.js`는 절차적으로 만든 설명용 네트워크를 그린다. 장면별 카메라 변화는 있지만 사용자가 선택한 실제 거래와 설명을 직접 연결하는 조작은 부족하다. 색상과 3D 분위기를 맞추는 것만으로는 DEUX처럼 읽히지 않는다.

| DEUX에서 효과적인 부분 | AML에서 구현할 대응 |
| --- | --- |
| 같은 로봇을 계속 본다 | 실제 CSV에서 추출한 같은 거래 부분망과 노드 ID를 유지한다 |
| 전체 로봇에서 특정 팔로 접근한다 | 전체 부분망에서 선택 거래의 송신·수신 계좌로 접근한다 |
| 버튼으로 중력보상 차이를 확인한다 | 거래 한 건만 보기 → 과거 1-hop → 과거 2-hop을 비교한다 |
| 불필요한 부품을 치워 초점을 만든다 | 선택과 관계없는 연결을 어둡게 하고 관련 경로만 펼친다 |
| 부품에 붙은 라벨 | 해당 계좌·거래 옆에 별칭, 시각, 금액·통화를 붙인다 |
| 브라우저 데모와 실제 영상의 구분 | 데이터 라벨, 설명용 연출, 논문의 모델 결과를 구분한다 |
| 장면 간 카메라 연결 | 같은 거래를 중심에 유지하면서 확대·초점·강조를 이어 간다 |

첫 구현의 중심 조작은 **한 거래의 관계 범위를 펼치는 것**으로 잡는다. 임의의 3D 구체나 입자를 추가해 풍성하게 보이게 하지 않는다. 거래 방향을 보여주는 움직임을 쓰더라도 실제 송금 속도나 모델 추론으로 오해하지 않게 표시한다. 거래 라벨을 계좌의 범죄 여부로 바꾸어 표현하지 않는다.

보고서의 성능 결과는 표·차트로 정확히 보여준다. 노드 색으로 모델 예측을 꾸며내지 않는다. 시간 기준 이후 연결을 제외하는 장면은 단순 장식이 아니라 시간 누수 방지 설명과 연결한다.

모바일은 참고 사이트의 강제 16:9 축소·가로 보기 안내를 그대로 가져오지 않는다. 사용자가 요청한 읽기 쉬운 2D 그래프와 세로 본문을 유지한다. 레퍼런스의 흰색 로봇 모델이나 자체 셰이더를 복사하지 않고 장면 설계 원리를 적용한다.

## 검토하지 않은 것

원본 저장소, 로봇 실험 재현, 실제 GPU 성능, 모든 영상의 전체 재생, 모바일 실기 전체 검수는 범위 밖이다. 이번 단계는 참고 사이트의 조작 분석이며 AML 사이트의 변경·배포 완료를 의미하지 않는다.


## 분석 후 적용한 사용자 결정 (2026-10-09)

사용자가 세로 본문보다 인터랙티브 PPT 형식을 원한다고 명확히 수정했다. 이에 AML은 모든 화면에서 16:9 비례 구도를 유지한다. 위 모바일 세로 본문 제안은 채택하지 않았다. 로봇 화면은 변경하지 않는다.

AML에 실제 부분망, 전체/대상 거래 접근, 과거 0·1·2-hop 범위 선택, 미래 연결 비교, 방향 재생, 드래그·확대·초기화를 구현했다. 카메라 이동은 0.95초이고 대상 계좌와 연결의 정체성은 유지한다. 표시 데이터는 26계좌·48거래이며 부분망의 선택 편향과 라이선스를 함께 공개한다. 결과 수치는 기존 원고 값을 유지한다.

검증: 데이터 무결성·원본 집계·시간 조건 테스트, Playwright 6개 창 크기 및 AML 상호작용, JavaScript/WebGL 대체 표시, 키보드·모션 설정, 기존 로봇 데모 회귀 검사 통과. 실물 휴대폰 성능은 별도로 측정하지 않았다.


## 발표 구성과 제목 효과 추가 (2026-10-10)

사용자 요청에 따라 목차 1장과 연구 설계·1차 성과·추가 분석·다음 단계 구분 4장을 추가해 총 12장으로 구성했다. 구분 화면은 밝은 민트색 바탕과 큰 번호·제목으로 발표의 리듬을 만든다. 목차와 각 구분 화면에서 내용을 바로 열 수 있다. 전체 페이지 수와 거래망 장면 번호를 분리하여 기존 데이터 조작을 유지한다.

제목은 줄바꿈과 최종 글자 자리를 유지한 채 순서대로 나타나며 최대 약 1초 안에 완성된다. 빠르게 이동하거나 움직임 줄이기를 켜면 남은 글자를 복원한다. 스크린리더에는 전체 제목을 제공하며 JavaScript가 없으면 원래 제목을 표시한다. 본문·수치에 반복 타이핑을 걸어 읽기를 지연시키지는 않는다.
